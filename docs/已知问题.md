## 一、已修（本轮）

### 1. Chinese++ 发行包缺 9 个别名 + 缺 `<driver>.cfg` — **已修**
- **现象**：装完直接写 `#包含 <C标准输入输出>` 或 `#包含 <向量>` 报 `找不到文件`；开发版正常。
  示例之所以能跑，是因为 `tasks.json` 手工补了 4 个 `-I`。
- **根因**：ZIP 不保留硬链接，发行包里只剩 `chinese++.exe` / `lld-link.exe` 两个真身；
  且 `install.ps1` 第 1b 步要调的 `tools\make_zhcfg.ps1` **在发行包里缺失**，所以 `bin\*.cfg` 从未生成。
  （`bin\*.cfg` 才是中文头搜索路径的来源 —— 开发版 `build\Release\bin\chinese++.cfg` 里就写着 5 条 `-isystem`。）
- **修法**：新增 `产物\生成中文头配置.ps1`（幂等）：补 8 个硬链接 + 写 5 份 `<driver>.cfg`（绝对路径、正斜杠、带引号）。
  接入三处：① `组装整合包.ps1` 拷完 C++ 立刻执行；② **安装器**装完用 `{app}` 真实路径重算；③ 脚本随包放在 `toolchains\cpp\`。
- **判据**：不带任何 `-I`，`chinese++ -std=c++20 你好.cpp` 退出码 0 且输出为空。**已验证通过。**
- **顺带**：示例的 C++ 任务去掉了 4 个 `-I`，并加 `-D_CRT_SECURE_NO_WARNINGS`（消掉 10 条 MSVC 弃用警告）。

### 2. TypeScript 的 `属于` 是 `for...in`，不是 `for...of` — **已修（示例与文档）**
- **现象**：`对于 (常量 值 属于 表)` 编译成 `for (const 值 in 表)`，`值` 是**字符串下标**，
  `值*2` 得 0/2/4 而不是 2/4/6。
- **实测**：`属于` → `for...in`（typeof string）；**`遍历` → `for...of`**（值 1/2/3，`值*2` = 2/4/6）。
- **修法**：`examples\typescript\你好.ts` 改用 `遍历`，注释写清两者区别；
  之前那份"类型推断 bug"的报告结论是**错的**，已删除。
- **遗留**：`属于`/`遍历` 这种一字之差的命名本身是**易错点**，建议 TS 线考虑（改名或报警告）。**归属：TS线。**

### 3. 文档里"引擎内嵌 ChinesePython"的说法 — **已修（文档）**
- **现象/事实**：引擎目录**没有 Python dll**；160 MB 主程序里搜不到 CPython / `Py_Initialize`；
  `--script res://x.py` 报"找不到该资源的载入器"。
- **结论**：引擎里能用中文写的是 **GDScript 的中文标识符**（上游 Godot 原生支持 Unicode 标识符）；
  只有**项目自带 `py4godot` 扩展**时才能用 ChinesePython 写游戏逻辑（本机测试项目就是那样）。
- **修法**：`说明.md` 与 `engine\说明.md` 已改正，不再声称内嵌 Python。

## 六、2026-11-07 第三轮反馈（P0/P1/P2，均已复现）

### P0-a 成员别名按"名字"全局替换（**静默产错结果**）— TS线
根因在本机源码：`E:\ChineseTypeScript\tsc\internal\scanner\zh_stdlib_generated.go`
是一张**扁平映射表**（`转字符串→toString`、`序列化→stringify`、`解析→parse`），
emit 阶段**按名字直接替换、不校验接收者**；而 `.zhts.*.d.ts` 里 `Object.toString` 会被 `JSON` 继承，
于是 `JSON.转字符串` 既能过类型检查（0 参签名），又被改写成 `JSON.toString`。

| 写法 | 实际生成 | 后果 | 正确写法 |
|---|---|---|---|
| `JSON.转字符串(甲)` | `JSON.toString(甲)` | `[object JSON]` | `JSON.序列化(甲)` |
| `承诺.解析(1)` | `Promise.parse(1)` | TypeError | `承诺.解决(1)` |
| `对象.键` | `object.键` | ReferenceError | `Object.keys()`（`对象` 是 `object` 关键字） |

**缓解（打包已做）**：`toolchains\typescript\中文成员名-陷阱与正确写法.md` 随包发出，标明正确写法与陷阱。
**根治**（TS线）：别名按接收者类型匹配，或别名表与 `.zhts.*.d.ts` 同源生成；并对"替换后类型不匹配"报错而不是静默 emit。

### P1-a 别名覆盖不全 — TS线
`连接`=connect（数组 join 是 **`连接成串`**）、`归约`=reduction（reduce 是 **`归纳`**）、
`圆周率` **实测可用**（在 `Lib\数学.py` 里实现，那张扁平表搜不到不代表没有 —— 我先前判错）。已写进陷阱表。

### P1-b Python 发行串带 dirty — Python线
实测 `3.14.7 (heads/chinese-python-dirty:522e8cc, Nov  6 2026, 20:06:25) [MSC v.1944]`
⇒ 发行版是从**未提交工作区**编的。判据：`sys.version` 不含 `dirty`。

### P2-a Java `字符串` 不是类型 — Java线
```
静态 字符串 问候()      → error: 找不到符号   符号: 类 字符串
字符串[] 数组 = {...}   → error: 找不到符号   符号: 类 字符串
```
⇒ `字符串` 只在部分位置被当类型，作为返回类型 / 数组元素类型都不认。

### P2-b 模块名猜错无提示 — Python线
`导入 异步库` → `模块未找到错误: 没有名为 '异步库' 的模块`（正确的是 `异步IO`）。
建议：`ImportError` 时对相近的中文模块名给 `Did you mean` 提示。
