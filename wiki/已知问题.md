## ⏳ 待修（需各语言线改）

| 归属 | 问题 | 判据 |
|---|---|---|
| **TS 线** | 成员别名**按名字全局替换**：`JSON.转字符串` → `JSON.toString`（静默输出 `[object JSON]`）、`承诺.解析` → `Promise.parse`（TypeError） | 按接收者类型匹配，或替换后类型不匹配就报错 |
| **TS 线** | 别名覆盖不全：`连接`=connect（join 是 `连接成串`）、`归约`=reduction（reduce 是 `归纳`） | 这三个词按直觉可用 |
| **TS 线** | 检查器报错后仍 emit | 报错的语句不产出代码 |
| **Python 线** | 发行串带 `-dirty`（未提交工作区编的） | `sys.version` 不含 dirty |
| **Python 线** | 模块名猜错无提示（`导入 异步库`） | 报错含相近名建议 |
| **Python 线** | `division by zero` / `True`/`None` 未汉化 | 除零消息为中文 |
| **Godot 线** | `--headless --editor --quit` 偶发 0xC0000005 | 连跑 5 次返回 0 |
| **Godot 线** | 运行栏缺「关闭引擎」按钮 | 见补丁说明 |
| **C++ 线** | `bundled`（不依赖 VS）底座未完成 | 设 bundled 时 `<vector>` 来自包内 |
| **C++ 线** | MSVC 头的 `note:` 是英文 | — |

## 🧭 不是 bug（有意为之）

| 现象 | 为什么 |
|---|---|
| Java 无 `字符串`/`列表` 等库类型中文名 | 那条线的口径：**只汉化关键字（L2）与诊断（L1），不汉化任何库名**。`字符串` 只是未定义的普通标识符（可当变量名，不能当类型） |
| 诊断前缀 `error:`/`warning:`/`note:` 保持英文 | 便于工具解析、与上游日志兼容；**正文**是中文 |
| 引擎不内嵌 CPython 于主程序 | 设计如此：GDExtension 的 dll 与 `Lib` 必须在磁盘上 |
| 无扩展市场、无微软账号 | 产品决定 |
| TS 的 `属于` = for-in | 语言设计（`遍历` 才是 for-of） |
